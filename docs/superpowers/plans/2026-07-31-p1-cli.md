# `openvhost` CLI v1 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** With the app running, `openvhost list --json | jq` prints the same services the GUI shows; `openvhost start nginx` blocks until it is genuinely up and exits 0; `openvhost stop-all` tears the stack down; a failure exits non-zero carrying the real stderr. With the app not running, `status` says so and exits **0** while control verbs exit 69 and name the fix.

**Architecture:** see the spec (`docs/superpowers/specs/2026-07-31-p1-cli-design.md`) — **READ IT FIRST for every task; D1–D7 are binding.** Transport, parsing and authorization live in `openvhost-proc::control`; *policy* lives in `apps/desktop/src-tauri/src/control.rs` behind a `ControlHandler` trait. `apps/cli` stays thin.

**Tech Stack:** Rust, tokio (`net` feature added), `clap` 4 (derive) in `apps/cli` only.

## Global Constraints

- SPDX headers on new files; `git commit -s`; Conventional Commits; **no `Co-Authored-By` trailer**.
- No `unwrap`/`expect` outside tests. **No `unsafe`** — use `tokio::net::UnixStream::peer_cred()`, never raw `LOCAL_PEERCRED`.
- `openvhost-proc` gains no `openvhost-core` and no `tauri` dependency. Nothing moves out of `quit.rs`.
- **No new Tauri command and no `capabilities/*.json` change.** If you think you need one, STOP and report — that is a design change.
- TDD with vacuity proof: every new test shown RED first (or neuter-proven); state the method per test group in your report.
- **Standing self-check** (report against each): vacuity proof per group; filesystem semantics (path length, symlinks, permissions, tempdir); reentrancy and lifecycle (what happens on a second connection, on shutdown, on a peer that connects and says nothing); exhaustiveness (no wildcard arms over request/response/state enums); and the **seams** — Task 2 and Task 3 are written against Task 1's published types with no review round in between, so those types must be right the first time.
- Gates per task: focused tests → `cargo test --workspace` → `cargo fmt --check && cargo clippy --workspace --all-targets -- -D warnings`. A known pre-existing flaky test lives in `openvhost-conf` (`settings::check::tests::a_non_zero_validator_exit_…`, a 5 s subprocess timeout under load) — rerun it in isolation if it trips and say so; do not fix it here.

## Dependency additions (Task 1 does these)

- Workspace `Cargo.toml`: add `"net"` to tokio's feature list (currently `process, rt-multi-thread, macros, sync, time, io-util` — `UnixListener`/`UnixStream` need `net`).
- `apps/cli/Cargo.toml`: add `openvhost-core` (path), `serde_json = "1"`, `clap = { version = "4", features = ["derive"] }`. **clap is not yet in `Cargo.lock`; 4.6.4 is in the local registry cache**, so `cargo add --offline` (or a hand-edited manifest plus `cargo build --offline`) works without network. If it does not, STOP and report rather than reaching for the network.

## Task 1: `openvhost_proc::control` — protocol, server, client

**Files:** `crates/openvhost-proc/src/control/{mod,protocol,server,client}.rs` (new), `crates/openvhost-proc/src/orphan/lock.rs`, workspace `Cargo.toml`.

**Published interface — Tasks 2 and 3 are written against exactly this, so get it right:**

```rust
pub const SCHEMA_VERSION: u32 = 1;
pub const MAX_REQUEST_BYTES: usize = 64 * 1024;
pub const READ_TIMEOUT: Duration = Duration::from_secs(2);
pub const MAX_SOCKET_PATH_BYTES: usize = 103;   // see spec D1: core's copy is unreachable from here
pub fn socket_path(home: &Path) -> Result<PathBuf, ControlError>;   // <home>/run/control.sock, length-checked

pub struct ServiceId(String);                    // parse-don't-validate at ingress
pub enum Request { Status { id: Option<ServiceId> }, List, Start { id: ServiceId, wait: bool },
                   Stop { id: ServiceId, wait: bool }, Restart { id: ServiceId, wait: bool }, StopAll }
pub enum Response { Services { services: Vec<ServiceStatus> },      // reuses the existing serde shape verbatim
                    Transition { service: ServiceStatus, disposition: Disposition },
                    StopAll { stragglers: Vec<String> },
                    Error { code: ErrorCode, message: String } }
pub enum Disposition { Changed, Unchanged }
pub enum ErrorCode { UnknownService, SupervisorUnavailable, ControlChannelUnavailable,
                     OperationFailed, Busy, Timeout, Unauthorized, BadRequest, UnsupportedVersion }

#[async_trait]  // or a plain boxed-future trait — desktop implements it
pub trait ControlHandler: Send + Sync {
    async fn execute(&self, req: Request) -> Response;
}

pub async fn serve(listener: UnixListener, handler: Arc<dyn ControlHandler>, shutdown: …);
pub fn bind(home: &Path) -> Result<UnixListener, ControlError>;   // unlink-if-socket, bind, chmod 0600
pub fn request(home: &Path, req: &Request) -> Result<Response, ControlError>;  // SYNC std client for the CLI
```

Also add to `orphan/lock.rs`:
```rust
pub enum SupervisorPresence { Present, Absent, Indeterminate { reason: String } }
pub fn probe(run_dir: &Path) -> SupervisorPresence;   // acquire-then-drop; no reaping, no side effects
```

Binding details from the spec: the envelope is `{"schemaVersion":1,"ok":…,"command":…,"result"|"error":…}` (D5); the request type **cannot express a path, argv or pid** (D6 — this is the containment invariant); `peer_is_authorized(peer_uid, our_uid)` is a pure function so it is testable; ingress is capped at `MAX_REQUEST_BYTES` **and** `READ_TIMEOUT` (D2); `bind` unlinks a stale path **only** when `symlink_metadata` proves it is a socket, refusing a symlink or any other type (D1).

- [ ] **Step 1:** Tests RED first — round-trip every `Request`/`Response` variant; an unknown op and an unknown `schemaVersion` each produce a *typed* error, never a silent no-op; `ServiceId::parse` rejects empty/oversized/control-character input; the size cap and the read deadline against a hand-fed reader; `peer_is_authorized`; `socket_path` rejects an over-long home; `bind` refuses a symlink at the socket path and refuses a regular file, but unlinks a real stale socket; `probe` returns all three variants (`Indeterminate` via an unreadable run dir).
- [ ] **Step 2:** A real-socket test in one process: a real client against a **recording fake handler** in a tempdir — happy path, oversized request, a peer that connects and sends nothing, mode is `0600`, and the **containment test**: a request naming an unregistered id is refused *and the fake records that no spawn was attempted*.
- [ ] **Step 3:** `cargo test --workspace`; fmt/clippy clean.
- [ ] **Step 4:** Commit: `feat(proc): authenticated local control socket`

## Task 2: desktop handler + wiring

**Files:** `apps/desktop/src-tauri/src/control.rs` (new), `lib.rs` (bind inside the `Ok(Some(lock))` arm only).

Implement `ControlHandler` over the managed `Arc<Supervisor>`:

- `List` / `Status` → `snapshot()`, id-sorted; `Status { id }` for an unregistered id → `UnknownService`.
- `Start`/`Stop`/`Restart` → **subscribe to `SupervisorEvent` *before* calling `start`/`stop`** (they are sync and only kick off the transition), then await the terminal state with a deadline; `Restart` sequences both halves server-side so a tray click or an Apply cannot interleave. Already in the target state → `Disposition::Unchanged`, exit-0 territory. `Failed` → `OperationFailed` carrying the `ServiceStatus` with its real `stderr_tail`. Deadline exceeded → `Timeout`. Per-service verbs take **no** lock (spec D7).
- `StopAll` → `BulkLock::try_lock` **and** the apply lock, exactly as the tray does; on contention return `Busy` (**reject, never queue**). On admission call `quit::stop_all(sup)` **verbatim** — do not fork it, do not move it — and return its stragglers.
- Binding: bind the socket **inside** the `Ok(Some(lock))` arm (spec D1: the socket exists iff a supervisor does); the degraded-boot arm must not bind. A bind failure is **not** fatal to the app — log it and continue; the GUI still works.

- [ ] **Step 1:** Tests RED first under the existing `mock_builder` harness with a real `Supervisor` driving `proc_testchild`: start reaches `Running` and the response carries it; a service that fails yields `OperationFailed` with the **stderr tail verbatim**; an already-running service yields `Unchanged`; an unregistered id yields `UnknownService` and nothing is spawned; `StopAll` while `BulkLock` is held yields `Busy` rather than queuing.
- [ ] **Step 2:** Implement + wire. `cargo test --workspace`; fmt/clippy.
- [ ] **Step 3:** Commit: `feat(desktop): serve the control socket from the supervisor owner`

## Task 3: the `openvhost` binary

**Files:** `apps/cli/src/{main,cli,render,exit}.rs`, `apps/cli/Cargo.toml`, `apps/cli/tests/two_process.rs`.

`clap` derive for `status [ID] | list | start ID | stop ID | restart ID | stop-all`, global `--json` and `--no-wait`. **Keep the existing `__testchild` subcommand working** — other crates' tests depend on it; hide it from `--help`.

Exit codes as one exhaustively-matched enum (spec D3): `0` success/unchanged · `64` usage · `66` unknown service · `69` supervisor or control channel unavailable · `70` operation/protocol failure · `75` busy or timeout · `77` unauthorized.

No-app behaviour (spec D3, the sharpest rule in the slice): `status`/`list` → **exit 0** with `"supervisor":"notRunning"` and an empty service list; every control verb → exit 69. Use `InstanceLock::probe` only to *improve the message*; the connect result is authoritative. **Never auto-launch.**

Output: in `--json`, exactly one single-line JSON object on stdout and **stderr empty** — errors go to stdout too so a `jq` pipeline still parses. In human mode, a readable table on stdout and errors on stderr.

- [ ] **Step 1:** Tests RED first — the exit-code mapping matched exhaustively over every `Response` variant and every client error; `--json` renders one line and nothing else; human rendering of a `Failed` service includes the stderr tail; bad args exit 64.
- [ ] **Step 2:** **The two-process test — the highest-value test in the slice.** `apps/cli/tests/two_process.rs` binds a real socket in a tempdir serving a fake handler, then runs the real `CARGO_BIN_EXE_openvhost` as a child with `OPENVHOST_HOME` set, asserting exit codes and exact JSON for: `list`, `start` success, `start` on an unknown id (66), and — with **no** server bound — `status` (exit **0**) versus `start` (exit 69). This is the only test proving the two-process story, and it needs no GUI.
- [ ] **Step 3:** `cargo test --workspace`; fmt/clippy. Commit: `feat(cli): openvhost start, stop, restart, status, list, stop-all`
