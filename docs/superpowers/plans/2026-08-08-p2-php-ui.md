# Plan — the Languages page stops requiring Homebrew (slice 5C)

Spec: `docs/superpowers/specs/2026-08-08-p2-php-ui-design.md`. Read it first; it is the contract
and this file does not restate it.

Branch `feat/p2-php-ui`, worktree `.claude/worktrees/php-ui`, based on `965eda1`.

**Run `pnpm install --offline --frozen-lockfile` in `apps/desktop` before the first desktop gate.**
A fresh worktree has no `node_modules` and the failure looks like a missing package, not a missing
install. This has cost time twice.

Two tasks. Each compiles and tests green at its end.

## T1 — Rust: the offer, the source on the wire, and the version that was always missing

Everything in `apps/desktop/src-tauri/src/`, plus whatever `openvhost-core` re-export it needs.

1. `PhpPackageOfferDto` per D1 — the same three variants as `MariadbPackageOfferDto`
   (`mariadb_pkg.rs:65`), **per major**, on the row rather than the environment.
2. `PhpRuntimeSourceDto` per D3, mirroring `NginxRuntimeSourceDto` (`commands.rs:1166`). This is
   the DTO 5B deliberately did **not** add; it belongs here.
3. **`full_version` finally carries something.** A packaged row reports the tree's patch version
   (`8.4.24`); a Homebrew row stays `None`. **Keep the existing comment explaining why brew rows
   are `None`** — update it, do not delete it as stale.
4. Route install by the row's offer (D4). The decision lives in Rust; the frontend does not
   re-derive the rule.

**Prove, and report each by name:**

- **Vacuity per test group.** Break it, watch it fail, restore it.
- **`full_version` is not `major` echoed.** The field's own comment names this trap explicitly.
  Assert a packaged row's `full_version` differs from its `major` and matches the tree.
- **No spawn** to produce a packaged row's version. 5B made this a compiler guarantee at the
  discovery layer (`discover_packaged` takes no probe argument) — show the DTO layer does not
  reintroduce one.
- **Exhaustiveness:** no wildcard arms on either new enum. Add a throwaway variant to each,
  record how many sites fail to compile, remove it, report the counts.
- **The `AwaitingRelease` path is what every offer resolves to today.** State that plainly and
  show what the row carries in that state.

## T2 — Svelte: the dead end becomes conditional, and the badge lands

1. **D2 is the whole task.** `LanguagesEmpty.svelte:77` currently gates on `!brewFound` before
   anything else. It must instead render only when there is **no route to a PHP at all** — no
   Homebrew, no packaged PHP installed, and no offer.
   **Do not soften the message.** When it does render, it renders as today, searched paths
   verbatim. The bug is that it is unconditional, not that it is blunt.
2. The source badge on packaged rows (D3). **Reuse MySQL's existing badge CSS line-for-line** —
   4C's review verified that rather than accepting a lookalike, and it is cheap to verify again.
   Confirm its palette stays disjoint from `StatusPill`'s so it cannot read as a status.
3. An `AwaitingRelease` row offers **no Install button** and says what it is waiting for.

**Prove, and report each by name:**

- **§8.1** — no Homebrew + a packaged PHP → the page lists it and the dead end does **not**
  render.
- **§8.2** — no Homebrew, no packaged PHP, no offer → the dead end renders exactly as today.
- **§8.6** — Homebrew present, no package tree → **nothing changes**. This is every real machine
  today. Say how you established it, not that you believe it.
- The badge cannot read as a status pill beside one.
- Vacuity per group, and **name any existing test whose expectation you had to change** — if one
  needs editing to stay green, that is a finding, not a chore.

## Binding on both tasks

- Report **against each proof obligation above by name**, including any that come out negative or
  that you could not do. A silent omission reads as a pass and will be treated as a finding.
- **No sub-agents.** Do the work yourself and report conclusions, not transcripts.
- Mutation experiments go in a **disposable worktree** and are removed afterwards; never leave a
  weakened check on disk. Stage by explicit path, never `git add -A`.
- **No browser automation of any kind.** Do not kill a process you did not start.
- Do not touch the user's real `~/.openvhost`, its `state.db`, `logs/`, any datadir or credential
  row, on any path including error paths.
- Conventional Commits, `git commit -s`. Write the message to a file and use `git commit -F
  <file>` — a bare `-n` in a commit message is read as `--no-verify` by this repo's hook.
- Gates: `cargo fmt --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo test --workspace`, `pnpm -C apps/desktop test`, `pnpm -C apps/desktop check`.
  **Never pipe a gate through `tail`** — the exit code you read becomes `tail`'s. Redirect to a
  file and check `$?`.
- If the task needs a design decision the spec does not make, **stop and report** rather than
  choosing. The last three slices each had a spec item that was wrong, and each time the
  implementer refusing it was worth more than compliance.
