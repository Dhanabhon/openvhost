# Tray / Menu-bar Quick Controls — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the window and the app keeps running; from the menu bar see the stack's state, start/stop everything or one service, get the real stderr when a tray-started service fails, and reopen the window from the tray or Dock. Quit still confirms and still leaves no children.

**Architecture:** see the spec (`docs/superpowers/specs/2026-07-31-p1-tray-design.md`) — READ IT FIRST for every task; D1–D10 are binding. The tray lives entirely in Rust under `apps/desktop/src-tauri/src/tray/`, reads the managed `Arc<Supervisor>`, and adds **no Tauri commands**. Bulk primitives sit beside `quit.rs`'s existing `stop_all`, which is shared verbatim.

**Tech Stack:** Rust + Tauri v2 (`tray-icon`, `muda`, `tauri-plugin-dialog` — all already resolved in `Cargo.lock`), SvelteKit only for the Rail button removal.

## Global Constraints

- SPDX headers on new files; `git commit -s`; Conventional Commits; **no `Co-Authored-By` trailer**.
- `openvhost-core` gains no tauri dependency. No `unwrap`/`expect` outside tests.
- **No new Tauri commands and no `capabilities/*.json` change** (spec D6). If you believe you need one, STOP and report — that is a design change, not an implementation detail.
- All menu mutations happen inside ONE `AppHandle::run_on_main_thread` closure (spec D2) — the setters are blocking main-thread round-trips.
- Menu state is **recomputed from `Supervisor::snapshot()`** and diffed; never applied as event deltas (spec D2).
- TDD with vacuity proof: every new test shown RED first (or neuter-proven), method stated per group in your report.
- Do NOT attempt to construct a real tray or muda menu in a test (spec D9). Test the pure model, the router by menu id, and `apply()` against a recording fake.
- Gates per task: focused tests → `cargo test --workspace` → `cargo fmt --check && cargo clippy --workspace --all-targets -- -D warnings` (+ `pnpm -C apps/desktop test`/`check` when the frontend is touched). A known pre-existing flaky test lives in `openvhost-conf` (`settings::check::tests::a_non_zero_validator_exit_…`, a 5 s subprocess timeout under load) — rerun it in isolation if it trips and say so; do not fix it here.

## Phase A — supervisor + model (Tasks 1–2)

### Task 1: `SupervisorEvent::Registered`

**Files:** `crates/openvhost-proc/src/{events,supervisor}.rs` (+ tests); consumers that match the event enum exhaustively.

Per spec D2: `Supervisor::register` currently emits nothing, so any service registered after launch (a newly installed PHP major, an initialized MySQL) never reaches an observer — the Services page has this bug today too. Add `Registered { status: ServiceStatus }` and emit it from `register`.

- [ ] **Step 3:** Implement; update the frontend store to react (a newly registered service appears without a restart) and regenerate bindings if the event crosses IPC.

### Task 2: the pure tray model

**Files:** `apps/desktop/src-tauri/src/tray/model.rs` (new; module registered but not yet wired to a real tray).

**Interfaces (contract for Task 3):**
```rust
pub struct TrayModel { /* summary line, per-service rows (id, label, enabled), bulk enablement, icon state */ }
pub enum IconState { Stopped, Running, Starting, Failed }   // matches docs/design/README.md's aggregate precedence
pub enum Action { Start(String), Stop(String), Retry(String), None }
pub fn tray_model(services: &[ServiceStatus], bulk: BulkState) -> TrayModel;
pub fn toggle_action(state: &ServiceState) -> Action;        // exhaustive, no wildcard
pub fn bulk_start_ids(services: &[ServiceStatus]) -> Vec<String>;
pub fn aggregate_icon(services: &[ServiceStatus]) -> IconState;
```

Binding details from the spec: rows are `"<Action> <name> — <State>"`, never a checkmark (D2); `Starting` rows are **disabled** (D3); `bulk_start_ids` selects **at most one service per distinct endpoint** (every `mysql-<major>` declares the literal `127.0.0.1:3306` — verified at `stack.rs:171`), skips non-terminal states, and skips `demo-ticker` (D6/D8); `aggregate_icon` follows `failed > starting > running > stopped` exactly (D5).

- [ ] **Step 1:** Tests RED first — every state's label and enablement; `toggle_action` exhaustive (add a variant mentally and confirm the match would fail to compile); two MySQL majors → one bulk id; two PHP majors → both; `demo-ticker` never in bulk; each aggregate precedence pair (a Failed among Runnings is Failed; a Starting among Stoppeds is Starting; …); empty service list.
- [ ] **Step 2:** Implement; `cargo test -p openvhost-desktop` (or the actual package name) green; fmt/clippy clean.
- [ ] **Step 3:** Commit: `feat(tray): pure menu model with aggregate icon state`

## Phase B — lifecycle + tray (Tasks 3–5)

### Task 3: hide-on-close, Reopen, and the `request_quit` show-first fix

**Files:** `apps/desktop/src-tauri/src/lib.rs` (the `CloseRequested` handler at ~:180 and the `.run(ctx)` call), `apps/desktop/src-tauri/src/quit.rs`.

Per spec D1. Three changes:
1. `CloseRequested` → hide the window, then `api.prevent_close()`. Only prevent the close if the hide **succeeded** — if hiding fails, let the close proceed rather than trapping the user in an app they cannot close.
2. Switch `.run(ctx)` to `.build(ctx)?.run(|handle, event| …)` and handle `RunEvent::Reopen` → show + unminimize + focus. **Preserve the existing fatal-error semantics on the build error** (the current `eprintln!` + exit path).
3. `quit::request_quit` must `show()` + `set_focus()` the main window **before** emitting `QuitRequestedEvent` — otherwise ⌘Q while hidden emits a confirmation into an invisible webview and the app silently refuses to quit. This is the sharpest interaction in the slice; give it its own test.

- [ ] **Step 1:** Tests RED first under the existing `mock_builder` harness (mirror `quit.rs`'s own tests): `request_quit` shows the window before emitting (assert ordering, not just that both happened); the close handler hides rather than quitting; a failed hide does not prevent the close.
- [ ] **Step 2:** Implement; `cargo test --workspace` green — **the existing quit tests are the regression net; they must pass unchanged.**
- [ ] **Step 3:** Commit: `feat(desktop): closing the window hides it instead of quitting`

### Task 4: the tray itself

**Files:** `apps/desktop/src-tauri/src/tray/{mod,apply}.rs`, `apps/desktop/src-tauri/icons/tray/*.png`, wiring in `lib.rs`.

Per spec D2/D5/D6/D9. Build the tray from `tray_model`; hold item handles; on each supervisor state event (and on `Registered`) recompute from `snapshot()`, diff, and apply **all** changes inside one `run_on_main_thread` closure; rebuild the menu only when the id set changes. Four template PNGs at 36×36 under `icons/tray/`, embedded (`include_image!`), `icon_as_template(true)`, **not** added to `bundle.icon`.

Router: `handle_tray_menu_id(&AppHandle, &str)` — takes an id, not a `MenuEvent`, so it is reachable under `mock_builder`. It re-reads `snapshot()` and derives the action from current state (never trusts the rendered label). Tray Quit shares `quit::QUIT_MENU_ITEM_ID` so the existing router handles it; when the UI-ready flag is false it calls `perform_quit` directly (spec D1's webview-independent escape).

- [ ] **Step 1:** Tests RED first: `apply(old, new, &RecordingSink)` emits exactly the expected set/enable calls for a representative transition and **nothing** when the model is unchanged; a membership change triggers a rebuild rather than a mutation; `handle_tray_menu_id` under `mock_builder` with a real managed `Supervisor` dispatches start/stop correctly and is a no-op for an unknown id.
- [ ] **Step 2:** Implement. Note the asset requirement: 36 px because `tray-icon` scales to 18 pt; an 18 px asset is blurry on Retina.
- [ ] **Step 3:** `cargo test --workspace` + fmt/clippy; commit: `feat(tray): live menu bar controls for every supervised service`

### Task 5: bulk actions, the failure dialog, and the two hygiene fixes

**Files:** `apps/desktop/src-tauri/src/tray/mod.rs` (or a sibling `service_control.rs`), `quit.rs` (share `stop_all`), `lib.rs` (`demo-ticker` gate), `apps/desktop/src/lib/components/Rail.svelte`.

Per spec D4/D6/D7/D8:
- `start_all` beside the existing `stop_all`, in the same closure-injected shape that made `stop_all_with` testable. **`stop_all` is shared verbatim** with quit — do not fork it.
- `BulkLock` (`tokio::sync::Mutex`) + a `try_lock` on the existing apply lock. **Reject, never queue**; the model disables Start all / Stop all while held. Per-service toggles take **no** lock (spec D7 — `start`/`stop` are already idempotent inside the entries mutex; verified).
- Failure dialog: track ids started **from the tray**; when one reaches `Failed`, show a native `tauri-plugin-dialog` error dialog with name, exit status and the bounded `stderr_tail` **verbatim**, buttons *Open OpenVHost* / *Dismiss*. The tray icon and row stay in the failed state after dismissal (spec D4 — the dialog is transient, the tray state is durable). Do **not** auto-open the window.
- `#[cfg(debug_assertions)]` on the `demo-ticker` registration at `lib.rs:251`.
- Remove the permanently-disabled "Stop all" button from `Rail.svelte:204`.

- [ ] **Step 1:** Tests RED first: `start_all_with` starts only terminal-state services and honours the one-per-endpoint rule; a second bulk action while one holds the lock is rejected (not queued); a bulk action is rejected while the apply lock is held; the dialog text contains the stderr tail verbatim; a *non*-tray-initiated failure does not raise a dialog.
- [ ] **Step 2:** Implement; `cargo test --workspace` + `pnpm -C apps/desktop test` + `check`; fmt/clippy.
- [ ] **Step 3:** Commit: `feat(tray): start all, stop all, and a native dialog for tray-started failures`
